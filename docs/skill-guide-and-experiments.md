# multi-agent-dev-flow · 作用说明与实验报告

> 版本：V1.0　日期：2026-10-04　实验环境：Windows 11 + Python 3（标准库，零第三方依赖）

---

## 一、这个 Skill 是做什么的

把「多个 AI Agent 协作完成全栈项目开发」的经验固化成可复用流程，覆盖需求梳理 → 美术风格确认 → 前端构建 → 后端搭建 → 数据库搭建 → 测试验收 → MVP → 迭代八个阶段。

它同时解决三个开发中的真实痛点：

| 痛点 | Skill 的对策 |
| --- | --- |
| **上下文长度危机**：单 AI 全包开发，对话越滚越长，后期开始"失忆" | master agent 只持任务指针；每个 agent 只读自己负责的文档；过程文档每轮归档，新 agent 冷启动只读 CHANGELOG 最新 3 条 |
| **AI 幻觉**：凭记忆复述接口字段、把"实现如此"当"应当如此" | 契约文档唯一事实源，引用字段必须回读原文；前端 × 后端 × 测试三方交叉校验；能用脚本验证的事实一律脚本验证 |
| **token 浪费**：让 AI 做 curl 验证、文档查缺、文件整理等体力活 | 四个零依赖 Python 脚本承担全部确定性工作，AI 只做设计与判断 |

## 二、组成部分及作用

### 2.1 流程层（SKILL.md + references/）

| 文件 | 作用 |
| --- | --- |
| `SKILL.md` | 触发入口：八阶段流水线、五条核心原则、各文件路由 |
| `references/workflow.md` | 每阶段的操作步骤、交付物验收标准、真实踩坑清单 |
| `references/frontend-paradigm.md` | 前端范式：HTML 预览先行、主题即配置、金额不前端算、契约消费纪律 |
| `references/backend-paradigm.md` | 后端范式：写操作五步法（鉴权→校验→幂等→事务→留痕）、统一错误码、金额整数分、时区显式锁定 |
| `references/database-paradigm.md` | 数据库范式：枚举状态机唯一登记、迁移脚本化、软删除、口径偏差声明 |
| `references/art-style.md` | 美术范式：风格指导文档 → HTML 预览 → 业主裁决 → 审查整改闭环 |
| `references/agent-collab.md` | 角色分工表、通信协议（只传文档路径不传内容）、防幻觉机制、契约变更硬规则 |
| `references/token-saving.md` | 三层资源分工（活上下文/文档系统/脚本系统）与脚本优先原则 |

### 2.2 模板层（assets/templates/）

PRD、美术风格指导、接口契约、测试用例、协作规范五套模板，复制即用，保证多 agent 产出的文档结构一致、可互相引用章节号。

### 2.3 脚本层（scripts/）——本报告实验对象

| 脚本 | 代替的 AI 劳动 |
| --- | --- |
| `contract_lint.py` | 逐行人工审查契约文档缺项（入参表/出参表/错误码/鉴权行） |
| `changelog_check.py` | 靠记忆检查"契约改了有没有同步 CHANGELOG" |
| `archive_memory.py` | 手动整理归档过程文档 |
| `probe_api.py` | 手工 curl 验证接口与返回码 |

## 三、实验设计与结果

### 实验 1：契约 lint —— 3 秒完成 AI 需要逐行 10 分钟的工作

**输入**：故意埋了 5 个缺项的示例契约（`orderCancel` 缺鉴权/入参/出参，`orderList` 入参表缺"必填"列、缺错误码小节）。

**结果**：

```
[ OK ] 2. 订单域 order > 2.1 orderCreate
[FAIL] 2. 订单域 order > 2.2 orderCancel
       - 缺少鉴权行（| 鉴权 | 公开/需登录/需权限点 |）
       - 缺少入参表
       - 缺少出参表
[FAIL] 2. 订单域 order > 2.3 orderList
       - 入参表表头缺列（应为 字段/类型/必填/含义/示例，实际：['字段', '类型', '含义']）
       - 缺少错误码小节

共检查 3 个接口，问题 5 个   （exit=1）
```

5 个埋入缺项全部命中，无误报。这类检查交给脚本后，AI 评审只关注语义正确性，上下文里不再需要装整份契约。

### 实验 2：CHANGELOG 守门 —— 硬规则的自动化，以及实验中发现并修复一个真 bug

**场景 A**：契约修改时间（10-04）晚于 CHANGELOG 最新条目（09-24）→ 报警 exit=1，提示"违反硬规则"。

**场景 B**：补上当日条目后，脚本仍报 FAIL —— **实验抓到一个真 bug**：原实现只取文件里第一个带日期的标题，而追加式（条目在文件尾）写法会取到最旧日期，永远误报。

**修复**：改为取所有条目标题中的最大日期，与条目排序方式无关。修复后场景 B 通过（exit=0），场景 A 回归后仍正确报警（exit=1）。

> 这正是 Skill 反复强调的机制的价值：规则写成脚本，bug 会在实验/CI 中立刻暴露；规则靠 AI 自觉，bug 会安静地漏进 68 轮迭代。

### 实验 3：记忆归档 —— 模拟 68 轮迭代后的过程文档

**输入**：`进度/` 目录 3 个轮次记录（mtime 分属 10-01/10-02/10-04）+ 1 个非文档文件 `capture.png`。

**结果**：3 个 md 按月份归入 `存档/存档-2026-10/进度/`，png 被自动排除，生成 `manifest.md` 清单（原路径、归档路径、大小可审计）。重复运行时目标重名自动加 `-2` 后缀，不覆盖已有归档。

### 实验 4：接口探针 —— 带幂等语义的模拟网关四连测

本地起模拟服务器（实现统一响应格式 + 幂等键拦截 + 参数校验 + 鉴权），探针验证四种场景全部符合预期：

| 场景 | 期望 | 结果 |
| --- | --- | --- |
| 正常下单 | code=0 | ✅ exit=0 |
| 同幂等键重试 | code=2002 幂等拦截 | ✅ 命中期望集 {0,2002} |
| 缺 addressId | code=1001 参数错误 | ✅ exit=0 |
| 未登录访问 | code=1002 | ✅ 命中期望集 {0,1002} |

探针按约定自动封装 `{"action","data"}` 请求体，退出码可直接接入 CI（0 绿 / 1 网络错误 / 2 断言失败），AI 全程无需手工 curl。

## 四、使用方式

**作为 Agent Skill**：把本仓库拷贝到 `~/.config/agents/skills/`（用户级）或 `<项目>/.agents/skills/`（项目级），对 AI 说"按 multi-agent-dev-flow 流程开发 XX 项目"即触发。

**脚本独立使用**（不依赖任何 AI）：

```bash
python scripts/contract_lint.py docs/api-contract.md
python scripts/changelog_check.py docs/api-contract.md CHANGELOG.md
python scripts/archive_memory.py 进度/ --into 存档
python scripts/probe_api.py -u <url> -a <action> -d '{"k":1}' -e 0,2002
```

## 五、结论

1. 四个脚本在全部实验场景下表现符合设计预期，可直接承担对应的基础工作；
2. 实验过程真实发现并修复了 `changelog_check.py` 的一个排序鲁棒性 bug，验证了"规则脚本化 + 实验验证"相对"AI 自觉执行"的可靠性优势；
3. Skill 的核心收益是结构性而非单点的：文档唯一事实源让小上下文多 agent 并行成为可能，脚本层把可验证事实从 AI 口述中剥离，两者叠加同时缓解上下文危机与幻觉问题。
