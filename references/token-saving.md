# Token 节省与本地资源利用

> 目标：把 AI token 花在只有 AI 能干的事（设计、判断、创作）上；凡确定性、重复性、可验证的工作，交给本地脚本与文档系统。这同时降低幻觉面——脚本输出没有幻觉。

## 1. 三层资源分工

| 层 | 载体 | 放什么 |
| --- | --- | --- |
| 活上下文 | 当前对话 | 本轮任务、待拍板问题 |
| 文档系统 | `docs/`、`CHANGELOG.md`、`存档-YYYY-MM/` | 全部事实性知识：需求、契约、设计、决策记录 |
| 脚本系统 | `scripts/` | 全部确定性操作：校验、探针、归档、迁移、对账 |

规则：**事实进文档，操作进脚本，对话只留判断。**

## 2. 记忆文档归档

- 每轮迭代产出的过程文档（需求单、排查记录、审核报告、会议纪要）在轮次结束时归档。
- 命名建议：`YYYY-MM-DD-第N轮-<主题>.md`；归档目录 `存档-YYYY-MM/`。
- `scripts/archive_memory.py` 自动完成：扫描、归类、生成清单、防止覆盖。
- 工作目录只保留"当前轮活跃文档"，降低每次会话的读取量。

## 3. 脚本清单（本项目自带，开箱即用）

| 脚本 | 代替的 AI 劳动 |
| --- | --- |
| `contract_lint.py` | AI 逐行检查契约文档完整性（入参/出参/错误码缺项） |
| `changelog_check.py` | AI 记忆"契约改了没同步 CHANGELOG" |
| `archive_memory.py` | AI 手动整理归档过程文档 |
| `probe_api.py` | AI 手工 curl 验证接口、判断返回码 |

扩展原则：发现自己在对话里第三次重复同一段验证逻辑 → 立即写成脚本入库。

## 4. 其他省 token 实践

- **新 agent 冷启动包**：新 agent 上线只读三样——CHANGELOG 最新 3 条、契约当前版、本角色范式文档。不读全量历史。
- **文档 grep 定位**：大文档（如 69KB 契约）用章节号 + 关键词定位读取，不整篇灌入上下文。
- **占位与剪枝**：部署包剔除开发依赖；对话中不粘贴长日志，落盘成文件后只传文件路径与关键行号。
- **多 agent 并行**：前端/后端/数据库并行施工，单 agent 上下文只装自己那一份，总量 = 最大单线上下文而非全部相加。

## 5. 防幻觉的成本逻辑

每加一个脚本/lint/探针，就堵住一个"AI 凭记忆口述事实"的口子：

- AI 说"接口已上线" → `probe_api.py` 探针说了算。
- AI 说"契约已同步" → `changelog_check.py` 守门。
- AI 说"文档没问题" → `contract_lint.py` 检查缺项。

**原则：可验证的事实，一律脚本验证；AI 只负责不可验证的判断。**
