# 前端工作范式

> 适用：小程序、Web 应用、管理后台等一切 UI 层。原则源自真实项目教训：UI 定稿先行、契约先行、主题即配置。

## 1. UI 先行：先有 HTML 预览，再有业务代码

1. 每个关键页面先做**纯 HTML+CSS 高保真静态预览**（占位数据），用户裁决后再写业务实现。
2. 预览稿即视觉基准：实现后逐页比对，差异写入《前端 UI 细节审核报告》（字号/按钮/间距/位置，按 P1/P2 分级）。
3. 有条件时做真机走查（开发者工具自动化截图比对），不只靠肉眼。

## 2. 主题即配置（Theming as Config）

- 一切视觉可变项（配色、Banner、分类、氛围元素）**数据库存储 + 接口下发**，前端用变量注入（CSS custom properties / 主题对象）。
- 换主题 = 缓存失效 + 版本号递增，**不允许为换主题改代码或发版**。
- 前端实现"主题缓存层"：启动拉取 `themeCurrent`，本地缓存，按版本号失效。

## 3. 接口消费纪律

- 所有请求走统一 request 封装：自动带 token、统一错误码处理、未登录（1002）跳登录、业务失败（2001/2002）toast 由封装层统一处理。
- **禁止前端计算金额**：单价、运费、优惠、总价一律以服务端返回为准，前端只渲染。前端本地求和只允许做"预览性展示"，提交永远以服务端重算结果为准。
- 消费任何接口前，先回读契约文档原文确认字段名与语义；禁止凭记忆写字段。
- 提交类操作必须防重复（按钮置灰 + 请求中锁），但不得依赖前端防重作为正确性保障——服务端幂等才是。

## 4. 状态与空态

每页至少实现四态：加载中（骨架屏）、空数据、加载失败（可重试）、无权限/未登录。PRD 未写也由前端 agent 补进契约缺口清单。

## 5. 文案纪律

- 界面文案一律引用《品牌与文案规范》，禁止现场编造。
- 敏感领域（食品、医疗、金融）遵守禁用词清单，功效类表述需资质支撑。

## 6. 自检清单（页面交付前逐项过）

- [ ] 与 UI 预览稿逐页比对无 P1 差异
- [ ] 所有消费接口已在契约文档登记且字段核对过
- [ ] 金额全部由服务端字段渲染，无前端求和
- [ ] 四态齐全
- [ ] 文案出自品牌规范
- [ ] 主题变量注入生效，切换主题无需改代码
